# Security policy

## Report a vulnerability privately

Private vulnerability reporting is currently **disabled** in the repository's
GitHub settings. The maintainers should enable it under **Settings → Code
security and analysis → Private vulnerability reporting** before accepting
sensitive reports.

Until the private advisory form is available, do not publish exploit details,
tokens, personal data, or reproduction steps in a public issue. A public issue
may ask for a private contact route, but must not include vulnerability details.
Once enabled, use the repository's
[private vulnerability reporting form](https://github.com/Ven4esters/RP-Chat-Overlay/security/advisories/new).

Include the affected version or commit, operating system, impact, and a minimal
reproduction when it is safe to share. Never attach real chat logs or credentials.
The maintainers will coordinate a fix and disclosure with the reporter.

There is no guaranteed response-time SLA. Do not assume a report has been
received until the maintainers acknowledge it through a private channel.

## Supported versions

Security fixes are made against the current default branch. Older releases are
not guaranteed to receive updates; upgrade to the latest release before
reporting an issue when possible.
