# Windows-сборка и релизная информация

## Создание EXE и сопутствующих файлов

В Windows 10/11 с Python 3.12 запустите `source/build_exe.bat`. Скрипт найдёт Python, создаст окружение, установит зависимости и соберёт `dist/FiveMChatOverlay.exe`. После успешной сборки он вызовет `source/tools/write_release_info.py` и положит рядом с EXE:

- `FiveMChatOverlay-README.txt` — версию, UTC-время сборки, размер, MD5/SHA-256, описание приложения, требования и ссылки;
- `FiveMChatOverlay.exe.md5`;
- `FiveMChatOverlay.exe.sha256`.

Готовый Windows-артефакт можно также собрать через GitHub Actions: **Build Windows exe → Run workflow**. При ручном запуске задание публикует EXE и три файла описания/контрольных сумм как downloadable artifact; в ветке сохраняются только небольшие TXT и sidecar-файлы. Сам EXE исключён из Git, чтобы не раздувать исходники. При сборке по тегу все четыре файла прикладываются к GitHub Release.

## VirusTotal

Сборочный скрипт не отправляет файлы в VirusTotal и не получает его вердикт. В TXT рядом с EXE указана страница отчёта/поиска по SHA-256; она сама по себе не подтверждает ни факт завершённого анализа, ни чистый результат.

Для настоящей проверки откройте страницу по SHA-256 или загрузите именно финальный EXE в VirusTotal, дождитесь отчёта и убедитесь, что SHA-256 в нём совпадает с `FiveMChatOverlay.exe.sha256`. При пересборке повторите расчёт сумм и проверку. Не публикуйте формулировку «проверено VirusTotal» без отчёта, относящегося к этой сумме.

### Почему возможны эвристические срабатывания

У этого приложения есть несколько свойств, которые могут повлиять на обобщённые эвристики и репутационные оценки:

- PyInstaller собирает однофайловый контейнер с Python и библиотеками; при запуске он распаковывает содержимое во временное место. Упаковщики, самораспаковка и новые хэши иногда получают generic/ML-детекты.
- Для работы предусмотрены настраиваемая глобальная клавиша Windows (`RegisterHotKey`) и отправка введённого пользователем текста в игровое окно через `SendInput`. В антивирусной эвристике эти API могут напоминать автоматизацию, перехват ввода или инъекцию.
- EXE не подписан Authenticode-сертификатом; у неподписанной сборки нет репутации проверенного издателя.
- Необязательный модуль DLX после явного согласия пользователя может загрузить и запустить отдельный бинарник сервиса перевода.

Это объясняет, **почему такие эвристики могут сработать в принципе**, но не устанавливает причину конкретной строки VirusTotal и не доказывает ложное срабатывание. Для точного объяснения нужны название движка, его метка/семейство и детали поведения из отчёта. Проверьте, относится ли отчёт к той же SHA-256; рассмотрите количество независимых детектов и sandbox-поведение; запросите перепроверку у конкретного вендора, если результат выглядит ошибочным. Нельзя называть файл ни «безопасным», ни «ложноположительным» только по агрегированному числу.
